# business-mcp-ru

MCP-серверы для российских деловых сервисов: **hh.ru, VK, Диадок, СБИС и Честный знак**.
Один пакет, пять серверов, 698 методов в каталоге. У каждого метода описание,
раздел и класс доступа: чтение, запись, необратимое. Перед записью агент обязан
спросить подтверждение.

```bash
uvx --from business-mcp-ru hh-mcp      # вакансии и отклики hh.ru
uvx --from business-mcp-ru vk-mcp      # сообщества, товары, реклама VK
uvx --from business-mcp-ru diadoc-mcp  # ЭДО Диадок
uvx --from business-mcp-ru sbis-mcp    # документооборот СБИС (Saby)
uvx --from business-mcp-ru crpt-mcp    # коды маркировки, Честный знак и СУЗ
```

## Что внутри

| Сервер | Методов | Откуда каталог | Чтение / запись / необратимое |
|---|---:|---|---|
| `hh-mcp` | **133** | официальная OpenAPI `api.hh.ru/openapi/specification/public` | 93 / 31 / 9 |
| `vk-mcp` | **373** | официальная схема `VKCOM/vk-api-schema` | 159 / 173 / 41 |
| `diadoc-mcp` | **114** | документация `developer.kontur.ru/doc/diadoc-api` | 79 / 28 / 7 |
| `sbis-mcp` | **45** | справка `saby.ru/help/integration/api` | 19 / 21 / 5 |
| `crpt-mcp` | **33** | открытые SDK True API и СУЗ | 24 / 9 / 0 |

Каталог не отдельный документ, а то, что сервер реально исполняет: тот же
`endpoints.yaml` грузится в рантайме и попадает в поиск по методам.

## Чем это отличается от обёртки над OpenAPI

Обёртка отдаёт агенту сотни функций и надеется, что он разберётся. Здесь
по-другому:

- **Поиск по методам словами.** `hh_search_methods("отклики на вакансию")`
  находит нужное по описанию и разделу, а не по имени эндпоинта.
- **Класс доступа у каждого метода.** `read` идёт сразу, `write` и
  `destructive` требуют подтверждения. Классификация проверяется тестами:
  `groups.ban` необратим, `groups.unban` это просто запись, `groups.getBanned`
  читает, и все трое различаются.
- **Токен не уходит на чужой хост.** У каждого сервера список разрешённых
  доменов, и заголовок авторизации не покидает его даже при вызове
  произвольного пути.
- **Пагинация описана в каталоге**, а не угадывается на месте.

## Честно про доступ

Сервисы отличаются не сложностью кода, а тем, как достаётся ключ.

- **hh.ru** — самый простой: приложение на `dev.hh.ru`, токен сразу. Обратите
  внимание на `HH_APP_NAME`: hh отклоняет запросы без внятного User-Agent.
- **VK** — сервисный ключ приложения или токен сообщества с нужными правами.
- **Диадок** — идентификатор приложения запрашивается у Контура письмом,
  токен пользователя выдаёт метод `Authenticate`. Для продуктива нужна лицензия.
- **СБИС** — идентификатор сессии от `СБИС.Аутентифицировать`, живёт ограниченное
  время и обновляется той же командой.
- **Честный знак** — токен ГИС МТ выдаётся в обмен на данные, подписанные КЭП
  (КриптоПро на машине пользователя). Подписание идёт вне сервера: закрытый
  ключ сюда не попадает и попадать не должен.

## Отдельно про каталог Честного знака

Документация ЦРПТ открывается только после входа по КЭП, публичной спеки нет
(`/api/v3/true-api/swagger.json` отдаёт 401). Поэтому пути в `crpt_mcp` взяты
из открытых SDK и у каждой записи стоит `verified: false`. Это карта для
разведки: пути надёжные, а глаголы и параметры надо подтверждать на живом
контуре. Сервер показывает этот статус в `describe_method`, чтобы агент не
выдавал догадку за факт.

## Переменные окружения

```
HH_TOKEN, HH_APP_NAME
VK_TOKEN
DIADOC_CLIENT_ID, DIADOC_TOKEN
SBIS_SESSION_ID
CRPT_TOKEN
```

Ключи можно не держать в окружении: у каждого сервера есть инструменты
управления кабинетами, они кладут ключи в локальный файл с правами 600.

## Как собираются каталоги

```bash
python3 scripts/ingest_openapi.py --spec hh.json --catalog hh_mcp/endpoints.yaml --prefix hh --host api.hh.ru --apply
python3 scripts/ingest_vk.py     --catalog vk_mcp/endpoints.yaml --apply
python3 scripts/ingest_diadoc.py --catalog diadoc_mcp/endpoints.yaml --apply
python3 scripts/ingest_sbis.py   --catalog sbis_mcp/endpoints.yaml --apply
python3 scripts/ingest_crpt.py   --catalog crpt_mcp/endpoints.yaml --apply
```

Скрипты аддитивны и идемпотентны: выверенные вручную класс доступа и ключевые
слова переживают повторный прогон.
